# 双分区固件升级功能使用说明

## 一、Application工程配置调整

### 1. 修改Keil工程配置（必须）

在Keil MDK中设置Application的起始地址：

1. 打开 `project/application/keil_project` 目录下的工程
2. 点击 `Options for Target`（或按 `Alt+F7`）
3. 选择 `Target` 标签页
4. 修改 `IROM1` 的起始地址：
   - 将 `Start:` 改为 `0x08004000`（对应APP0分区起始地址）
   - `Size:` 设置为 `0xA000`（40KB，对应APP0分区大小）
5. 点击 `OK` 保存

### 2. 修改向量表偏移（已完成）

文件 `project/application/startup/system_stm32f10x.c` 中：
- `VECT_TAB_OFFSET` 已设置为 `0x4000`（对应APP0起始地址偏移）
- 这确保中断向量表正确指向APP0分区

### 3. Application代码无需特殊处理

Application的代码可以正常编写，无需知道Bootloader的存在。Bootloader会自动跳转到APP0运行。

**注意**：Application固件大小不能超过40KB！

---

## 二、Bootloader配置

### 1. 分区配置（已配置）

在 `project/bootloader/main/upgrade_config.h` 中：
- **Bootloader**: 16KB (0x08000000 - 0x08004000)
- **APP0**: 40KB (0x08004000 - 0x0800E000) - 运行分区
- **APP1**: 40KB (0x0800E000 - 0x08018000) - 升级暂存分区

### 2. 串口配置

- **串口1 (USART1)**: 用于Xmodem协议接收固件数据
- **串口2 (USART2)**: 用于打印升级流程信息（调试用）

## 三、完整使用流程

### 步骤1：编译Bootloader

1. 打开 `project/bootloader/keil_project` 工程
2. 编译生成 `bootloader.bin` 文件
3. 使用ST-Link或其他烧录工具将bootloader烧录到STM32的 **0x08000000** 地址

### 步骤2：编译Application

1. 打开 `project/application/keil_project` 工程
2. **重要**：确认IROM1起始地址为 `0x08004000`
3. 编译生成 `application.bin` 文件
4. 固件大小不能超过40KB

### 步骤3：Bootloader主程序配置

在Bootloader的 `main.c` 中需要初始化串口和固件升级模块：

```c
#include "firmware_upgrade.h"
#include "drv_comm.h"
#include "system.h"

int main(void)
{
    // 系统初始化
    SysTick_Init(72);
    NVIC_PriorityGroupConfig(NVIC_PriorityGroup_2);
    
    // 初始化串口1（用于Xmodem接收固件）
    drv_usart_init(DRV_USART_ID_1, 115200, NULL);
    
    // 初始化串口2（用于打印升级信息，可选）
    drv_usart_init(DRV_USART_ID_2, 115200, NULL);
    
    // 初始化固件升级模块
    firmware_upgrade_init(DRV_USART_ID_1);
    
    // 检查APP0是否有效
    if (firmware_upgrade_is_app_valid())
    {
        // APP0有效，延迟3秒后跳转（给用户时间进入升级模式）
        delay_ms(3000);
        firmware_upgrade_jump_to_app();
    }
    else
    {
        // APP0无效，等待固件升级
        firmware_upgrade_start();
    }
    
    // 主循环
    while(1)
    {
        // 处理固件升级
        firmware_upgrade_process();
        
        // 检查升级状态
        uint8_t state = firmware_upgrade_get_state();
        if (state == FW_UPGRADE_STATE_COMPLETE)
        {
            // 升级完成，跳转到APP0
            delay_ms(1000);
            firmware_upgrade_jump_to_app();
        }
        else if (state == FW_UPGRADE_STATE_ERROR)
        {
            // 升级失败，可以重新启动
            firmware_upgrade_stop();
            delay_ms(1000);
            firmware_upgrade_start();
        }
        
        delay_ms(10);
    }
}
```

### 步骤4：使用Xmodem工具发送固件

#### Windows系统：

```bash
# 安装pyserial库
pip install pyserial

# 发送固件（使用1024字节模式，推荐）
python tools/xmodem_sender.py COM3 115200 application.bin

# 或使用128字节模式（更稳定但较慢）
python tools/xmodem_sender.py COM3 115200 application.bin --128
```

#### Linux系统：

```bash
pip install pyserial
python3 tools/xmodem_sender.py /dev/ttyUSB0 115200 application.bin
```

**注意**：
- 将 `COM3` 或 `/dev/ttyUSB0` 替换为实际的串口1设备
- 波特率必须为115200
- 固件文件必须是 `application.bin` 格式

## 四、升级流程说明

### 1. 接收阶段
- Xmodem协议通过串口1接收固件数据
- 数据直接写入APP1分区（升级暂存区）
- 每接收4KB显示一次进度

### 2. 校验阶段
- 接收完成后自动校验APP1分区的固件
- 检查向量表有效性
- 检查堆栈指针和复位处理函数地址

### 3. 升级阶段
- 校验通过后，擦除APP0分区
- 从APP1逐块读取数据并写入APP0
- 每10%显示一次复制进度
- 最后校验APP0数据完整性

### 4. 完成阶段
- 升级完成后自动跳转到APP0运行
- 如果升级失败，可以重新启动升级流程

## 五、注意事项

### 1. 固件大小限制
- Application固件大小不能超过40KB
- 如果固件过大，需要优化代码或减少功能

### 2. 串口配置
- 串口1和串口2的波特率必须都是115200
- 串口1用于数据传输，串口2用于调试信息

### 3. 升级时机
- Bootloader启动后3秒内可以进入升级模式
- 如果3秒内没有收到升级数据，会自动跳转到APP0
- 可以在APP0中实现跳回Bootloader的功能

### 4. 错误处理
- 如果升级失败，Bootloader会停留在升级模式
- 可以重新发送固件进行重试
- 升级过程中不要断电

### 5. Application代码要求
- Application代码起始地址必须为0x08004000
- 向量表偏移必须设置为0x4000
- Application代码不需要知道Bootloader的存在

## 六、常见问题

### Q1: 升级后无法运行？
**A**: 检查以下几点：
- Application的起始地址是否为0x08004000
- 向量表偏移是否为0x4000
- 固件大小是否超过40KB
- 固件是否完整

### Q2: 串口2没有打印信息？
**A**: 检查串口2是否已初始化，波特率是否为115200

### Q3: Xmodem传输失败？
**A**: 检查：
- 串口1连接是否正常
- 波特率是否匹配（115200）
- 串口线是否稳定
- 可以尝试使用128字节模式（--128参数）

### Q4: 如何从APP0跳回Bootloader？
**A**: 在APP0中实现软复位或跳转功能，跳转到0x08000000地址
